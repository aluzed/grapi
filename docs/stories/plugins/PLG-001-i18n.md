# PLG-001 : i18n

## Contexte
Dans Strapi 5, i18n fait partie du socle : il est toujours actif, mais un content type n'est localisé que si `pluginOptions.i18n.localized: true`. Chaque locale d'un document est une ligne distincte qui partage le même `documentId`. Les champs non localisés sont recopiés sur toutes les locales.

## Objectif
La gestion des locales et le contenu multilingue, avec la même sémantique que Strapi.

## Périmètre
- Table `i18n_locale` (name, code unique). La liste ISO des locales est embarquée.
- Locale par défaut dans le core store (`plugin_i18n_default_locale`). La première locale vient de `STRAPI_PLUGIN_I18N_INIT_LOCALE_CODE`, alias grapi `GRAPI_I18N_INIT_LOCALE_CODE`, et vaut `en` par défaut.
- Injection dans chaque content type :
  - une colonne `locale` (string) ;
  - une relation virtuelle `localizations` jointe sur `document_id`, privée si le type n'est pas localisé.
- Attribut localisé ou non : `pluginOptions.i18n.localized` par attribut. Un champ non localisé est recopié sur toutes les locales après chaque écriture, dans la même transaction.
- Paramètre `locale` sur le Document Service et l'API REST :
  - défaut : la locale par défaut ;
  - `*` : toutes les locales, pour findMany, count, delete, publish, unpublish et discardDraft ;
  - un `update` sur une locale inexistante crée cette locale en copiant les champs non localisés.
- Relations entre types localisés :
  - les deux côtés localisés : la cible est forcée dans la locale de la source ;
  - seule la cible localisée : on prend `relation.locale` ou, à défaut, la locale de la source ;
  - sinon, pas de locale.
- Routes :
  - Content API : `GET /api/i18n/locales` ;
  - admin : CRUD `/i18n/locales` (on ne peut pas supprimer la locale par défaut), `GET /i18n/iso-locales` ;
  - Content Manager : `GET /i18n/content-manager/get-fill-from-locale/:model`, `POST /i18n/content-manager/actions/get-non-localized-fields`.
- Permissions par locale dans le RBAC admin (`properties.locales`, `AUTH-001`). Il n'y en a pas sur le Content API, comme chez Strapi.
- Supprimer une locale supprime toutes les lignes de cette locale (avec confirmation dans l'UI).
- Passer un type de localisé à non localisé, ou l'inverse (via `ADM-006`) : on garde la locale par défaut et on supprime les autres, comme Strapi, avec un avertissement explicite.

## Hors périmètre
- Traduction automatique par IA (fonction cloud de Strapi). Elle pourra se brancher plus tard sur le générateur LLM de grapi, hors parité.

## Critères d'acceptation
- [x] Banc `SETUP-002` : create en `en`, update en `fr` (qui crée la locale), find avec `locale=fr`, `locale=*` et sans locale donnent des réponses identiques à Strapi.
- [x] Modifier un champ non localisé en `fr` met à jour `en` (intégration).
- [x] Une relation entre deux types localisés reste dans la même locale (banc).
- [ ] Publier avec `locale: '*'` publie toutes les locales (intégration avec `DOC-002`).
- [ ] La suppression de la locale par défaut est refusée.
- [ ] **Compat DB (D3)** : les locales et contenus localisés d'une base Strapi existante sont lus tels quels.

## Avancement
- Banc `i18n-dp` en mode grapi, SQLite et Postgres : 92/92 (création, mise à jour qui crée une locale, `locale=fr`, `locale=*`, synchronisation des champs non localisés, relations entre types localisés, single types localisés, suppressions par locale), et le contrôle inverse (Strapi relit les écritures de grapi). `GET /api/i18n/locales`, locale initiale créée au bootstrap (`internal/bootstrap`).
- Reste : routes admin (CRUD des locales, `iso-locales`, actions du Content Manager), liste ISO embarquée, publication `locale: '*'` vérifiée, refus de supprimer la locale par défaut.

## Notes techniques
- La logique de locale vit dans le Document Service (`DOC-001`, `DOC-006`). Ce plugin fournit le modèle, les routes et la synchro des champs non localisés via un middleware de document (`DOC-004`).
- Pas de recopie si le type n'est pas localisé : une seule ligne par statut.
